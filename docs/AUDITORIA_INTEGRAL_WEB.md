# Auditoría integral de Finabiz.mx

22 de noviembre de 2026 · Base de revisión: `main` en `26be3a9c6e11489389a7bb761a0afa3baca24f26`.

La [reauditoría UX/UI del 23 de noviembre](REAUDITORIA_UX_UI_2026-11-23.md) revisa la producción posterior al PR #42, contrasta los hallazgos de esta línea base y registra las incidencias vigentes.

## Reconocimiento

Sitio estático con HTML, CSS y JavaScript nativo. El árbol base contiene 35 documentos HTML, `assets/site.css` para interiores, `image-slot.js` y recursos locales en `assets/`. La portada concentra sus estilos, esquemas y scripts en `index.html`. No se encontraron manifiestos de aplicación, backend, suites de pruebas ni workflows versionados. `.nojekyll`, `CNAME` y las cabeceras públicas corroboran GitHub Pages. La fuente exacta de Pages en Settings queda por confirmar.

Los PR #16–26 constan como fusionados. #16 separó dos entradas y tres áreas. #17 cambió el recorrido. #18 y #19 documentan la retirada de WebGL y la carga diferida del widget. #20 introdujo disclosures nativos. #21 añadió el panel del hero y refinó ejemplos. #22 modificó fallbacks, ARIA y pantallas pequeñas. #23 retiró las cifras del hero. #24–26 iteraron el mensaje hasta el copy actual. [Historial de pull requests](https://github.com/finabizmx/finabiz-site/pulls?q=is%3Apr+is%3Aclosed)

Orden del DOM base: hero → servicios → método → ejemplos → firma → propuesta → diferenciadores → equipo → FAQ → contacto → pie. El hero responde qué hace la firma y para quién. Las dos necesidades orientan al visitante hacia tres áreas y los ejemplos muestran el tipo de información que recibirá. La explicación de contratación queda repartida entre método, FAQ y contacto. Los tres bloques de firma, propuesta y diferenciadores repiten anticipación fiscal, utilidad y equipo integrado. El menú ofrece servicios, método, blog y contacto. La estructura es compatible con el recorrido aprobado y permite reducir redundancias sin reordenar las secciones.

## Verificaciones transversales

- **SEO.** El sitemap enumera 29 URLs canónicas del dominio raíz. Robots permite rastreo y referencia ese sitemap. El recorrido estático de los 35 HTML encontró tres destinos internos inexistentes, todos en la plantilla editorial. La portada tiene title, descripción, canonical, Open Graph, Twitter Cards y JSON-LD. Páginas de servicios ya cubren ecommerce, agencias, infoproductores, cumplimiento y cálculo. Conviene comprobar solapamiento por consulta antes de crear nuevas rutas. La ruta inexistente probada devolvió 404. Quedan por validar indexación real en Search Console, resultados enriquecidos y señales locales verificables.
- **Accesibilidad.** El parser encontró un H1 por documento salvo el redirect `detective/`; no detectó duplicados de ID ni imágenes HTML sin atributo alt. Eso no valida calidad de textos alternativos, SVG, contenido generado, orden de foco ni conformidad WCAG. Servicios y FAQ usan `details/summary`. Los ejemplos usan botones con `aria-pressed`; con scripts desactivados el contenido está en el DOM. Deben probarse expansión, foco tras saltos, controles táctiles, zoom 400 %, 320 CSS px, orientación corta, VoiceOver y TalkBack.
- **Seguridad.** GA4, Typeform, Google Fonts, Calendly y WhatsApp forman parte del recorrido público. La portada conserva UTMs en sesión. El identificador de GA y el ID de formulario son públicos por diseño. Una búsqueda de patrones comunes de claves privadas, AWS, GitHub y Stripe en el árbol actual no arrojó coincidencias. La misma búsqueda en el historial disponible tampoco detectó coincidencias. Pendiente ampliar la detección a otros formatos, comprobar terceros y revisar avisos y configuración de consentimiento con acceso autorizado. Una URL con `noindex` sigue siendo pública.
- **Producción.** Las 29 URLs del sitemap devolvieron HTTP 200 sin redirección por el proxy. El raíz IPv4 resolvió a 185.199.108.153–185.199.111.153. WWW resolvió a 15.197.225.128 y 3.33.251.168. No se obtuvo IPv6 para raíz ni www en ese resolvedor. El dominio `finabizmx.github.io` sí resolvió en ambas familias. El origen raíz devolvió HTTP 200 sobre HTTPS y HTTP 301 hacia HTTPS por el proxy del entorno. Caché observada del documento: 600 s. Typeform devolvió 200 para el endpoint público. Google Public DNS corroboró los A y la ausencia de AAAA para raíz y www, devolvió ns47 y ns48.domaincontrol.com como NS y no devolvió CNAME para www. La respuesta raíz coincide byte a byte con el blob Git. El proxy aceptó TLS para raíz y www; queda pendiente inspeccionar directamente emisor, SAN, cadena y vencimiento. El entorno no representa Telcel ni Defender VPN.
- **Rendimiento.** Los tamaños de fuente Git sirven de referencia. La comparación de Lighthouse local se detalla abajo. Quedan por medir CWV de campo, cobertura de interacciones y laboratorio con recursos externos activos. PageSpeed Insights API devolvió 429 por cuota. Se midió un TTFB de 1.17 s por proxy para la portada en una solicitud y 0.89 s para Arquitectura. Son observaciones puntuales de red; los tiempos de curl por proxy no representan CWV. La performance debe medirse en portada, arquitectura, servicio, blog y calculadora, con perfiles móvil y escritorio y varias ejecuciones.
- **Backend.** El contacto se apoya en proveedores externos y no se acreditó una necesidad actual de servidor propio. El caso de un CRM o una automatización debe justificarse con pérdidas observadas, requisitos de atribución y costo de operación. Las configuraciones remotas de Typeform, Calendly y GA4 quedan pendientes de confirmación, incluido el registro del lead y la cita.

## Evidencia adicional de proveedores y accesibilidad

La respuesta pública de Typeform configura un formulario en español, enlaza el aviso simplificado al pedir datos de contacto, exige confirmar la lectura del aviso y deja opcionales las comunicaciones comerciales. Tiene un paso obligatorio de Calendly y una pantalla de confirmación. Ese flujo no demuestra que se utilice `agenda.html`. Antes de modificar o retirar esa ruta, confirmar si sigue enlazada desde correos, campañas o integraciones externas. El ajuste público `show_cookie_consent` del formulario está desactivado. Corresponde revisar el consentimiento de rastreo junto con el de GA y Calendly. La inspección se hizo sin enviar respuestas. [Formulario de orientación](https://form.typeform.com/to/ykt2ayIi)

Axe-core 4.10.3 se ejecutó en Chromium a 390×844, con recursos externos bloqueados. Detectó contraste insuficiente en inicio, arquitectura, ecommerce, privacidad, agenda y blog. Marcó tamaños de destino en el pie, falta de landmark principal en varias plantillas y una región desplazable que no recibe foco en el comparador (`.cmp`). El landmark de inicio dejó de fallar con el primer cambio de #28. Lighthouse identificó que el nombre del enlace de marca omitía su texto visible, un salto a H4 en el pie y que el H1 era el elemento LCP con retraso de renderizado. El segundo commit de #28 ajusta el nombre, los encabezados y el tamaño de enlaces legales y muestra el hero desde el primer pintado. Los resultados automatizados deben complementarse con revisión de fondos, estados y dispositivos. [PR de portada](https://github.com/finabizmx/finabiz-site/pull/28)

El menú compacto depende de JavaScript para desplegar sus enlaces. La prueba sin scripts verificó que los seis enlaces de reserva siguen disponibles y que los ejemplos quedan en el DOM sin el atributo `hidden`. Continúa pendiente mejorar el acceso al menú en ese modo.
